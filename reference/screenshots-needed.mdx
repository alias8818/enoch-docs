# Screenshot needs

This docs pass did not fabricate screenshots. The most useful images require a clean demo deployment or user-provided runtime views.

## Needed screenshots

1. **Main dashboard overview** — `/dashboard` with non-secret sample queue, status, and paper data.
2. **Control status data** — `/control/api/status` rendered in a terminal or dashboard view with tokens redacted.
3. **Worker preflight result** — successful `/control/api/preflight` response with secrets redacted.
4. **Dry-run dispatch response** — `/control/dispatch-next` with `dry_run: true` and no private hostnames.
5. **Paper review detail** — a generated artifact review item showing checklist, evidence links, and status, with private paths redacted.
6. **Corpus artifact folder** — public GitHub view of one artifact containing `paper.md`, `metadata.json`, `evidence_bundle.json`, `claim_ledger.json`, and `paper_manifest.json`.
7. **Hugging Face dataset preview** — `data/artifacts.jsonl` fields and dataset card caveat.

## Redaction rules

Before adding screenshots, remove or blur bearer tokens, API keys, Notion IDs, private hostnames, LAN IPs, user names, home paths, unpublished logs, provider credentials, and production queue state.

## Optional diagrams

Static diagrams can be source-generated without a live system: idea intake to queue handoff, control VM and worker wake-gate deployment, evidence bundle to generated artifact to corpus export, and authorship/provenance responsibility split.
