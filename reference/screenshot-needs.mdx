The current docs should not invent product screenshots. Real screenshots require a running Enoch deployment with non-secret sample data, because the dashboard, queue, worker wake gate, and paper review views are runtime surfaces. Until those captures exist, use text diagrams and command examples instead of placeholder product images.

<Warning>
Never capture bearer tokens, private project names, private run logs, LAN-only hostnames, personal notes, or unpublished research artifacts in public docs screenshots. Use a disposable local config and sample queue rows.
</Warning>

## Required runtime captures

| Need | Where it would help | Capture requirements |
|---|---|---|
| Control dashboard overview | `introduction`, `deployment`, `reference/api-endpoints` | `GET /control/dashboard` loaded with sample queue state, token hidden, no private URLs. |
| Dispatch safety status | `guides/dispatch-flow`, `concepts/control-plane` | Dashboard or JSON output showing `dispatch_safe`, `dispatch_blockers`, `active_items`, and `next_candidate` for a non-sensitive demo item. |
| Worker wake gate state | `concepts/wake-gate`, `reference/troubleshooting` | Worker dashboard with a demo run moving through waiting/quiet-window states; no process command lines containing secrets. |
| Paper review queue | `guides/paper-artifacts`, `reference/authorship-provenance` | Review queue with AI-generated artifact caveat visible and sample checklist states. |
| Evidence artifact folder | `concepts/evidence-and-artifacts` | File tree or editor capture showing `paper.md`, `paper.tex`, `evidence_bundle.json`, `claim_ledger.json`, and `paper_manifest.json` for a demo run. |
| Local quickstart success | `quickstart` | Terminal output from `scripts/smoke-test-local.sh` with randomized local token redacted. |

## Placeholder assets

The repository currently includes `images/sample-feature-light.png` and `images/sample-feature-dark.png`. They are not referenced by any MDX page and should remain unused unless they are replaced with real, reviewed captures from a safe demo deployment.

## Capture checklist

Before adding an image to these docs:

1. Reproduce the view from the public repository and documented config only.
2. Redact tokens, hostnames, private project names, and local paths that identify private infrastructure.
3. Add alt text that states what the screenshot proves.
4. Link the page text to the source-grounded workflow instead of using the screenshot as the only instruction.
5. Run `node scripts/validate-docs.mjs` and `mint broken-links` when the Mintlify CLI is available.
