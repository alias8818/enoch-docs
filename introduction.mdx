Enoch is an agentic research control plane that treats autonomous AI work as a reliability engineering problem, not a scripting problem. It queues research ideas sourced from an upstream LLM scouting process, gates dispatch through authenticated preflight checks, supervises agent runs on local AI hardware using process-tree tracking and CPU/GPU telemetry, captures evidence into structured bundles, and generates publication-style research artifacts with provenance instead of free-floating model output. Every transition in this pipeline is guarded by idempotent APIs, stale-state reconciliation, and operator-visible status — so you always know what is running, what is queued, and what the hardware is actually doing.

## The problem Enoch solves

Long-running autonomous AI work fails in ways ordinary scripts do not:

- Child processes continue after an agent session appears idle.
- GPU workers can still be active when queue state says no work is running.
- Queues become stale or disagree across sources.
- Evidence scatters across machines and run folders.
- Generated reports overstate results when claim boundaries are not preserved.

Enoch treats these as control-plane problems, not model problems. It uses process tracking, CPU/GPU quiet-window telemetry, idempotent APIs, stale-state reconciliation, a live dashboard, evidence bundles, and claim ledgers to make autonomous work observable and auditable.

## Architecture flow

The full pipeline from research idea to published artifact follows this sequence:

```text
LLM research scout
  -> structured idea cards
  -> Notion scoring / weight matrix
  -> queue candidate
  -> VM control plane
  -> worker preflight and dispatch safety checks
  -> GB10 worker wake gate
  -> agent run with process + telemetry supervision
  -> evidence sync
  -> AI-generated research artifact
  -> corpus quality gates
```

Runtime authority begins when a scored candidate becomes a queue item in the Enoch control plane. From that point forward, safety and truth come from control-plane state, worker preflight, wake-gate telemetry, process tracking, and evidence artifacts — not from optimistic signals from the agent session itself.

## Key components

<CardGroup cols={2}>
  <Card title="Control plane API" icon="server">
    Manages queue state, project state, paper review state, pause and maintenance controls, and dispatch decisions. Built with FastAPI and a LangGraph-era graph/state model.
  </Card>
  <Card title="Wake gate" icon="shield-check">
    Proves a run is actually done, not just agent-session-closed. Tracks process trees and sustains CPU/GPU quiet-window telemetry over a configurable window before marking work complete.
  </Card>
  <Card title="Worker preflight" icon="stethoscope">
    Runs authenticated health checks against the worker machine before dispatching new work. Dispatch fails early and visibly rather than silently producing a bad run.
  </Card>
  <Card title="Single-lane safety" icon="lock">
    Prevents overlapping GPU-heavy work on constrained local hardware. The control plane holds the exclusive dispatch lock — not the dispatch script — so the guarantee is centrally enforced.
  </Card>
  <Card title="Evidence sync" icon="arrow-down-to-bracket">
    Copies run notes, metrics, result summaries, evidence bundles, and claim ledgers from worker project folders into the control plane before artifact generation begins.
  </Card>
  <Card title="Artifact writer" icon="file-pen">
    Generates publication-style Markdown reports from evidence context while preserving uncertainty and provenance. Does not free-float against raw model output.
  </Card>
  <Card title="Quality gates" icon="circle-check">
    Scans generated reports for placeholder citations, missing provenance, and missing evidence artifacts before they enter the corpus. Nothing publishes until the gates pass.
  </Card>
</CardGroup>

## What makes Enoch different

Most prompt-automation setups rely on the agent session to report its own completion status. Enoch treats that signal as untrustworthy by design. The wake gate requires sustained telemetry evidence — CPU idle below threshold, GPU idle below threshold, no active child processes from the tracked run — held over a configurable quiet window before a run is considered done. This means your queue cannot advance on a lie.

The same discipline applies at every boundary: the control plane holds queue locks rather than leaving them to dispatch scripts; evidence sync runs before the artifact writer has access to any context; quality gates block publication rather than warning after the fact. Enoch is reliability engineering around agentic AI work, not just a scheduler on top of it.
