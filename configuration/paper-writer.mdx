# Paper writer settings

The paper writer creates generated research-artifact drafts from collected evidence context. It does not make a paper peer reviewed, human authored, or scientifically validated.

## Providers

### `deterministic`

The default provider. It produces template-based output without calling an external LLM. Use it for local testing and predictable behavior.

### `synthetic.new`

An optional OpenAI-compatible provider path. The example config uses `https://api.synthetic.new/openai/v1` and `hf:zai-org/GLM-5.1`. Aliases in the code include `synthetic`, `synthetic_glm`, and `template` for compatibility. Keep docs and new configs explicit.

## Fields

- `paper_writer_provider`
- `paper_writer_base_url`
- `paper_writer_model`
- `paper_writer_api_key`
- `paper_writer_timeout_sec`
- `paper_writer_temperature`
- `paper_writer_max_tokens`
- `paper_writer_fallback_enabled`

If `paper_writer_api_key` is empty, provider code can look for `SYNTHETIC_API_KEY`. Do not commit API keys.

## Fallback behavior

When fallback is enabled, provider failure can fall back to deterministic output. That is operationally useful, but reviewers should still inspect the draft and its evidence before finalization.

## Publication rule

Generated drafts should not enter the public corpus until provenance and quality gates pass and a human has accepted the limitations.
