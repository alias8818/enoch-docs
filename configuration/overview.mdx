Enoch reads its configuration from a single JSON file whose path you set in the `OMX_WAKE_GATE_CONFIG` environment variable. Every field is validated at startup using Pydantic; the service refuses to start if a required field is missing or a value is out of range. This page documents every top-level field, shows you how to generate the secure tokens the service needs, and walks through the complete annotated example from `config.example.json`.

<Warning>
  Never commit your live config file to version control. It contains bearer tokens and callback credentials that grant full control over your deployment. Use a secrets manager or environment-specific file that is excluded from your repository.
</Warning>

## Loading the config file

Set `OMX_WAKE_GATE_CONFIG` before starting the service:

```bash
export OMX_WAKE_GATE_CONFIG=/etc/enoch/config.json
```

The systemd unit provided in `deploy/` sets this variable automatically. For local development you can export it in your shell or prefix the start command directly.

## Generating secure tokens

All bearer tokens in the config must be long random strings. Generate one with:

```bash
python3 -c "import secrets; print(secrets.token_urlsafe(48))"
```

Run this command separately for each token — `omx_inbound_bearer_token`, `completion_callback_token`, and `worker_wake_gate_bearer_token` must all be distinct values.

## Required fields

<ParamField path="omx_inbound_bearer_token" type="string" required>
  Authenticates all dashboard and control API calls as well as incoming OMX event posts. Pass this value as a `Bearer` token in the `Authorization` header when calling the control-plane API or the dashboard.
</ParamField>

<ParamField path="completion_callback_url" type="string" required>
  URL that the wake gate calls when a gated run completes. Point this at your automation webhook or downstream service.
</ParamField>

<ParamField path="completion_callback_token" type="string" required>
  Bearer token the wake gate sends with every completion callback request. Your webhook endpoint should validate this value before processing the event.
</ParamField>

<ParamField path="state_dir" type="string" required>
  Absolute or `~`-prefixed path to the local durable state directory. The service stores queue state, run records, and internal databases here. Defaults to `~/.local/state/omx-wake-gate` if not overridden.
</ParamField>

<ParamField path="project_root" type="string" required>
  Root directory for project workspaces and generated paper artifacts. Each project gets a subdirectory under this path. Defaults to `~/enoch/projects`.
</ParamField>

<ParamField path="dispatch_script_path" type="string" required>
  Path to the shell script the control plane executes to launch agent runs. Defaults to `~/enoch/bin/enoch_omx_dispatch.sh`. Ensure the script is executable and accessible by the service user.
</ParamField>

## Wake-gate tuning fields

These fields control how the wake gate decides that a workload has become idle and it is safe to fire the completion callback. All are optional and have sensible defaults.

<ParamField path="listen_host" type="string" default="0.0.0.0">
  Network interface the HTTP server binds to.
</ParamField>

<ParamField path="listen_port" type="number" default="8787">
  TCP port the HTTP server listens on.
</ParamField>

<ParamField path="sample_interval_sec" type="number" default="5">
  How often (in seconds) the gate samples CPU and GPU telemetry. Minimum value is `1`.
</ParamField>

<ParamField path="idle_sustain_sec" type="number" default="180">
  How long (in seconds) all idle thresholds must remain satisfied before the gate considers the workload complete. Minimum value is `30`.
</ParamField>

<ParamField path="cpu_idle_threshold_pct" type="number" default="35.0">
  CPU utilisation percentage below which the gate counts a sample as idle. Range `0.0`–`100.0`.
</ParamField>

<ParamField path="gpu_idle_avg_threshold_pct" type="number" default="10.0">
  Average GPU utilisation percentage below which a sample is considered idle. Range `0.0`–`100.0`.
</ParamField>

<ParamField path="gpu_idle_peak_threshold_pct" type="number" default="20.0">
  Peak GPU utilisation percentage below which a sample is considered idle. Range `0.0`–`100.0`.
</ParamField>

<ParamField path="vram_delta_threshold_mib" type="number" default="1024">
  Maximum VRAM change in MiB between consecutive samples that is still counted as idle. Set to `0` to require no VRAM movement.
</ParamField>

<ParamField path="max_wait_after_idle_sec" type="number" default="43200">
  Hard ceiling (in seconds) on how long the gate will wait for a workload to become idle before timing out. Minimum value is `60`.
</ParamField>

<ParamField path="default_workload_class" type="string" default="inference_eval">
  Workload class applied when a dispatch request does not specify one. Valid values are `inference_eval`, `training`, `control_plane`, and `agent_harness`. Each class maps to a threshold profile; `inference_eval` applies stricter idle requirements (longer sustain, lower CPU threshold) than `training`.
</ParamField>

<Tip>
  You can override per-workload thresholds using the `workload_profiles` map in your config. Define an object keyed by workload class name with the same fields as `GateThresholdProfile` (`idle_sustain_sec`, `cpu_idle_threshold_pct`, `gpu_idle_avg_threshold_pct`, `gpu_idle_peak_threshold_pct`, `vram_delta_threshold_mib`).
</Tip>
